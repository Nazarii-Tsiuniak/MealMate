# MealMate: REST CRUD для лабораторної роботи №6–7

Ізольована демонстрація: `HttpClient` + локальний `HttpServer` Dart, без нових пакетів.
Основний RecipeRepository, каталог, план харчування, покупки та їх дизайн не змінюються.
SQLite та серверної авторизації немає. Сервер слухає лише 127.0.0.1.

## Запуск у Windows та Android-емуляторі

Відкрийте два термінали PowerShell у `D:\IPZ-43\App`.
Flutter/Dart мають бути в PATH. Інакше замініть `dart` на
`& 'C:\flutter\flutter\bin\dart.bat'`, а `flutter` на
`& 'C:\flutter\flutter\bin\flutter.bat'`.

Термінал 1 — сервер; залиште працювати, Ctrl+C зупиняє:

```powershell
cd D:\IPZ-43\App
dart run tool/rest_demo_server.dart --delay-ms=700
```

Термінал 2 — окрема debug-демонстрація:

```powershell
flutter devices
flutter run --debug -d emulator-5554 -t lib/main_rest_demo.dart
```

Використовуйте фактичний Android device ID з `flutter devices`.
Android-емулятор бачить localhost комп’ютера як **10.0.2.2**, а не localhost.
Типова адреса клієнта — `http://10.0.2.2:8080`.
Для іншого порту запустіть сервер з `--port=8765`, а клієнт так:

```powershell
flutter run --debug -d emulator-5554 -t lib/main_rest_demo.dart --dart-define=REST_BASE_URL=http://10.0.2.2:8765
```

Звичайний MealMate: `flutter run -d emulator-5554 -t lib/main.dart`.
П’ятої вкладки немає. Окрема точка входу показує демонстрацію тільки в debug;
у profile/release вона відкриває звичайний застосунок.
Локальний HTTP дозволено лише в debug Android для 10.0.2.2, 127.0.0.1 та localhost.
Release-маніфест не змінено. Інші платформи не створювалися.

## Дані та параметри сервера

- `--port=8080` — порт.
- `--delay-ms=700` — необов’язкова затримка для наочного індикатора (0–5000 мс).
- `--data=шлях_до_JSON` — власний файл даних.

Типове сховище: `.dart_tool/rest_demo/recipes.json`, початково шість деморецептів.
POST/PUT/DELETE справді зберігають зміни у файлі; перезапуск сервера їх не скидає.
`flutter clean` може видалити `.dart_tool`; для збереження лабораторних даних
використовуйте власний `--data=...` (шлях із пробілами беріть у лапки).
Пошкоджений файл не замінюється демоданими — сервер повідомить про помилку.
Призначення сервера — локальна лабораторна демонстрація, без публічного доступу.

## Перевірка операцій на екрані

1. **GET · Отримати**: `GET /recipes` → **200**, список серверних рецептів.
   Перший GET виконується автоматично. Індикатор та вимкнені кнопки позначають очікування.
2. **Новий зразок JSON**: змініть `name` у редакторі; **POST · Створити** → **201**.
   ID створює сервер. Основний каталог MealMate не поповнюється цим рецептом.
3. Виберіть картку серверного рецепта. Змініть JSON, наприклад назву або кількість
   інгредієнта. **PUT · Зберегти**: `PUT /recipes/{id}` → **200**.
   PUT замінює весь рецепт, тому JSON має містити всі обов’язкові поля.
4. Повторний GET підтверджує збережені зміни.
5. **DELETE · Видалити** → діалог підтвердження → `DELETE /recipes/{id}` → **204**
   без тіла. Наступний GET підтверджує відсутність рецепта.
6. Зупиніть сервер та натисніть GET: побачите повідомлення про мережеву помилку.
   Запустіть сервер повторно й повторіть GET.

Екран показує українські повідомлення успіху/помилок та журнал останніх 12 запитів
із HTTP-статусами. Некоректний JSON не надсилається. Таймаут — 10 секунд.
Автоматичних повторів немає: після таймауту перевірте стан через GET, перш ніж
повторювати POST, оскільки сервер міг зберегти запис до втрати відповіді.
Прокручування закриває клавіатуру.

## JSON-контракт POST / PUT

```json
{
  "name": "Демонстраційний омлет",
  "description": "Рецепт для лабораторної",
  "category": "breakfast",
  "preparationMinutes": 15,
  "calories": 320,
  "servings": 2,
  "ingredients": [
    {"name": "Яйця", "quantity": 3, "unit": "шт", "note": null},
    {"name": "Сіль", "quantity": null, "unit": null, "note": "за смаком"}
  ],
  "preparationSteps": ["Збийте яйця", "Приготуйте омлет"]
}
```

Категорії: breakfast, lunch, dinner, salad, dessert.
Одиниці: г, кг, мл, л, шт. Для «за смаком» quantity/unit = null, note = «за смаком».
JSON використовує десяткову крапку. Відповідь рецепта додатково містить `id`.
GET повертає масив таких об’єктів. Наявні моделі повторно використані без змін.

Статуси помилок сервера: 400 — JSON/валідація; 404 — маршрут/рецепт відсутній;
405 — непідтримуваний метод; 500 — помилка сервера/запису файлу.
Потрібен Content-Type: application/json; максимальне тіло — 64 КіБ.

## Перевірка реальних HTTP-запитів без UI

Поки сервер працює:

```powershell
dart run tool/rest_demo_check.dart
# За іншого порту:
dart run tool/rest_demo_check.dart http://127.0.0.1:8765
```

Скрипт виконує GET → POST → GET → PUT → GET → DELETE → GET, перевіряє збереження
кожної зміни та видаляє лише власний тестовий рецепт. Сервер друкує метод, маршрут і статус.
Для перевірки перезапуску створіть рецепт через UI, перезапустіть сервер з тим самим
JSON-файлом та виконайте GET.

## Скріншоти для лабораторного звіту

- Термінал із запуском API, адресою та шляхом JSON-файлу.
- Завантаження «Виконується HTTP-запит…» (використайте `--delay-ms=1500`).
- GET: серверний каталог і журнал `GET /recipes → HTTP 200`.
- POST: створений рецепт, серверний ID, повідомлення успіху та HTTP 201.
- PUT: змінена назва/JSON, повідомлення успіху та HTTP 200.
- DELETE: діалог, потім повідомлення успіху й HTTP 204; наступний GET без рецепта.
- Помилка мережі після зупинки сервера або помилка JSON.
- Термінал зі статичним аналізом і успішними тестами.

## Фактична Android-перевірка

На emulator-5554 успішно зібрано й запущено окрему debug-точку входу.
Через 10.0.2.2:8765 виконано GET 200, POST 201, PUT 200, підтверджений DELETE 204.
Після зупинки сервера екран показав «Немає з’єднання з API. Перевірте адресу та запуск сервера».
Тестовий сервер після перевірки зупинено. Для власної демонстрації запустіть сервер
і екран командами вище (типовий порт 8080). Скріншоти автоматично не зберігалися.
