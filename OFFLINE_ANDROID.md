# MealMate — автономний Android

Запуск із кореня проєкту:

```powershell
flutter run --flavor offline -d emulator-5554 -t lib/main_offline.dart
```

FastAPI та інтернет не потрібні. Серверна точка входу `lib/main.dart` і backend збережені. Окремий release APK на цьому етапі не збирається.

SQLite `mealmate_offline.db` зберігається у приватному каталозі Android. Версії: 1 — профіль/метадані, 2 — рецепти, 3 — план, 4 — покупки. Профіль, рецепти, інгредієнти, кроки, план, порції, ручні покупки, позначки й навмисні видалення зберігаються після перезапуску. Калорії та діаграма обчислюються з цих даних.

## Початкові рецепти

`lib/data/demo/offline_recipe_seed.dart` містить оригінальні 10 рецептів із `backend/scripts/demo_recipes.py`, із тими самими інгредієнтами, порціями, ккал і кроками. На чистій базі — 10. Старі шість рецептів попередніх офлайн-етапів не видаляються: на такій установці може бути 16 плюс власні рецепти. Seed версії 2 виконується один раз; видалені й відредаговані рецепти після цього не відновлюються автоматично.

## Резервна копія на телефоні

Аватар → Профіль → Резервні копії:

- «Зберегти резервну копію» — системний діалог Android записує JSON у вибране місце, наприклад Downloads.
- «Імпортувати / відновити» — вибір JSON та явне підтвердження. Власна резервна копія замінює локальний стан; серверний експорт об’єднується за стабільними ID.
- Перед імпортом у тій самій транзакції зберігається попередній стан. «Зберегти попередню копію» дозволяє експортувати його і відновити через той самий діалог. Історія містить останній попередній стан.

Некоректні файли та порушені зв’язки відхиляються; SQL-помилка відкочує імпорт. Формат версійний, ліміт файлу — 10 МБ. JWT, паролі та хеші не експортуються. JSON містить особисті харчові дані й не шифрується; зберігайте його у власному сховищі. Видалення застосунку/очищення даних стирає приватну SQLite, тому перед цим збережіть копію окремо.

## Одноразовий експорт серверного акаунта

Інструмент відкриває джерело тільки для читання, експортує один обраний акаунт і відмовляється перезаписувати наявний файл:

```powershell
.\backend\.venv\Scripts\python.exe .\tool\export_server_data.py --database .\backend\data\mealmate.db --user-email "your-email@example.com" --output .\exports\mealmate-server-export.json
```

Вкажіть свій email; пароль не потрібний. Передайте JSON на телефон, тоді відкрийте імпорт у профілі. Це одноразове перенесення, без фонової синхронізації. ID десяти оригінальних seed-рецептів зіставляються з офлайн-ID, щоб не дублювати ці рецепти. Власні серверні рецепти зберігають свої ID. Повторний імпорт оновлює однакові ID; решта локальних рецептів зберігається. Каталог exports виключений із Git.

## Перевірки

```powershell
flutter analyze
flutter test
$testTemp = Join-Path ([System.IO.Path]::GetTempPath()) ('mealmate-export-' + [guid]::NewGuid().ToString('N'))
.\backend\.venv\Scripts\python.exe -m pytest tool/test_export_server_data.py -q --basetemp=$testTemp
```

Автоматичні тести використовують тільки тимчасові SQLite. Тести offline_app перевіряють запуск із забороненим HTTP, всі чотири вкладки та чинний редактор рецептів. offline_domain перевіряє відновлення плану, дробові порції, калорії, покупки, видалення, резервні копії, імпорт і rollback.

Якщо Windows-збірка нового файлового плагіна повідомляє про Kotlin incremental caches, для поточного PowerShell-процесу можна вимкнути incremental-компілювання без очищення даних:

```powershell
$env:GRADLE_OPTS = '-Dorg.gradle.project.kotlin.incremental=false -Dorg.gradle.project.kotlin.compiler.execution.strategy=in-process'
flutter run --flavor offline -d emulator-5554 -t lib/main_offline.dart
```

Це не змінює Android applicationId, підпис або дані емулятора. Після закриття цього термінала налаштування не зберігається.

## Остання перевірка реалізації

- Flutter: 170 PASS, 1 штатний SKIP live FastAPI; flutter analyze без зауважень.
- Read-only експортер: 2 PASS на синтетичних серверних SQLite.
- На emulator-5554 перевірено всі чотири вкладки, системне збереження JSON і відновлення щойно збереженої копії.
- Після примусового завершення й повторного запуску процесу SQLite v4 зберегла всі записи; integrity_check та foreign_key_check успішні.
- На наявному емуляторі збережено 6 попередніх рецептів і додано 10 оригінальних: разом 16. Дані не очищалися.
- HTTP примусово заборонений у widget-тестах офлайн-запуску й чотирьох вкладок; ці тести пройшли.
- Серверна SQLite, backend та серверні точки входу не змінювалися. Release APK, commit і push не виконувалися.
