# MealMate — перевірка перед завершенням лабораторної роботи №6–7

## Середовище та результати

Перевірено тільки Android-застосунок. Flutter 3.47.6, Dart 3.13.5.
Емулятор: emulator-5554, Android 17 / API 37, android-x64; екран 1080×2400.

- `dart format lib test`: 67 файлів, форматування завершено.
- `flutter analyze`: No issues found! (2,4 с).
- `flutter test`: **74 тести пройшли**, помилок немає (приблизно 21 с).
- `flutter run -d emulator-5554 --no-resident`: debug APK зібрано, встановлено й запущено.
- У журналі Flutter поточного запуску не знайдено EXCEPTION / overflow / assertion.

Початкові 52 тести збережено. Додано 22 регресійні перевірки: 18 сценаріїв
адаптивності, 3 наскрізні сценарії та перевірку контрасту.

## Автоматизоване покриття

- Валідація входу й реєстрації, show/hide пароля, переходи та демонстраційний вхід.
- Повернення з реєстрації, деталей та форми системною кнопкою «Назад».
- Після входу стек не містить LoginScreen. Вкладки не створюють додаткових маршрутів.
- Скасування створення/редагування, збереження запиту й категорії каталогу між переходами.
- Повний CRUD рецептів, підтвердження та скасування видалення.
- Перевірка порожніх форм, незаповнених рядків, додавання/видалення інгредієнтів і кроків,
  збереження текстів та порядку кроків після видалення рядків.
- Некоректні числові значення: 0 для додатних полів, від’ємні, дроби для цілих полів,
  текст, NaN, Infinity, переповнення int та `1e999` для кількості.
  Десяткова кома допустима; калорійність 0 і порожня необов’язкова калорійність допустимі.
- Новий рецепт доступний у пошуку та категоріях.
- План: нормалізація дат, один запис на дату/тип їжі, додавання, заміна, видалення,
  зміна тижнів, межі місяців/років, очищення посилань після видалення рецепта.
- Прогрес: 0/21 і 21/21; на головній відповідно 0% і 100%.
- Покупки: повторення рецептів, нормалізація назв, г/кг, мл/л, шт, несумісні одиниці,
  «за смаком», відсутність дублікатів, ручне додавання/редагування/видалення.
- Збереження ручних продуктів, незмінених статусів придбання та скидання статусу
  при зміні кількості, ізоляція тижнів, повторне відкриття, очищення з підтвердженням.
- Зміна рецепта або плану автоматично оновлює покупки; видалення рецепта прибирає
  відповідні записи плану й автоматичні покупки, що підтверджено також наскрізним тестом.

## Адаптивність і usability

Widget-тести: 280×480, 320×568 та 640×360 логічних пікселів; текст 200%,
верхні/нижні safe insets по 24, клавіатура 180 px на формах. Окремі наявні
тести також перевіряють шрифт 150% і клавіатуру 180/240 px.
Перевірено вхід, реєстрацію, деталі з довгими назвами/описами/інструкціями,
форму рецепта, форму продукту та всі вкладки. До плану й покупок додано довгі назви.
Перевірено доступність нижніх кнопок, прокручування та діалогів.

Виявлені та виправлені проблеми:

1. **Overflow логотипа авторизації** на вузьких екранах зі шрифтом 200%.
   Логотип масштабується вниз лише за нестачі місця; кнопка повернення має власне місце.
2. **Overflow діалогу видалення рецепта** з довгою назвою; кнопки могли опинитися поза екраном.
   Увімкнено прокручування вмісту, підтвердження й скасування доступні.
3. **Overflow діалогу очищення покупок** на малих екранах зі збільшеним шрифтом.
   Також увімкнено прокручування.
4. **Недостатній контраст допоміжного тексту**: 3,51:1 на білому,
   3,41:1 на основному фоні, 2,87:1 на світло-зеленому.
   Колір змінено з #7E8C85 на #5C6B63: відповідно 5,62:1, 5,45:1, 4,60:1.
5. **Замала ширина натискання дат**: 42 dp на вузьких екранах.
   Мінімальна ширина комірки збільшена до 54 dp, активна область — щонайменше 48 dp;
   календар зберігає горизонтальне прокручування.

## Реально перевірено на Android-емуляторі

- Реєстрація → системне повернення → демонстраційний вхід.
- Нижня навігація; головна → план; додавання омлету; системне повернення на головну.
- Прогрес головної 1/21 і 5%; головна → покупки, автоматична поява 4 продуктів.
- Checkbox → 1/4; наступний тиждень порожній; повернення зберігає позначку.
- Ручний продукт QA-product у режимі «за смаком» → прогрес 1/5.
- Каталог → деталі → редагування → скасування: назва залишилася незмінною.
- Редагування кількості яєць 3 → 4, збереження → актуальні деталі й покупки.
  Незмінна придбана зелень і ручний продукт збереглися.
- Видалення сніданку з плану → автоматичні продукти зникли, ручний залишився.
- Очищення: скасування зберігає продукт; підтвердження очищує список.
- Візуально перевірено форму рецептів та прокручування продуктів до останньої позиції.

## Межі перевірки та залишкові обмеження

Підтверджених невиправлених помилок у перевірених сценаріях бізнес-логіки немає.
На емуляторі плаваюча панель апаратної клавіатури іноді накривала кнопку збереження;
прокручування форми закривало її, після цього збереження успішне.
Це не видається за виправлену проблему IME; конфігурацію клавіатури не змінювали.
Раніше повідомлене введення українською з фізичної клавіатури ноутбука повторно не перевірялося.

Повний CRUD створення/видалення, усі невалідні числа, пошук/фільтрація нових рецептів,
видалення рецепта з очищенням залежностей і матриця малих екранів перевірені тестами,
але не повторені повністю вручну на емуляторі.
Фізичні Android-пристрої, інші версії Android, TalkBack, системні жести різних оболонок,
release-збірка та тривалі навантажувальні сценарії не перевірялися.

Профіль і відновлення пароля залишаються чесно позначеними заглушками.
Сховище лише в пам’яті, авторизація демонстраційна; втрата змін після завершення
процесу очікувана. Backend, REST API, SQLite, нові залежності й платформи не додавалися.
